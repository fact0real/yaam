# YAAM privacy and network connections

Reviewed against the source on 18 October 2026. This describes application behavior, not the retention policies of external providers. It incorporates and corrects the network draft supplied by EA3JIC.

Every network peer can see your public IP address (or your proxy/VPN address), connection timing and ordinary request metadata. “No station payload” below does not mean anonymous access. DNS, macOS/iCloud services and remote web page subresources can make additional connections. This is a source review, not a packet-capture audit.

YAAM can contact public data services without an account. The CelesTrak, NOAA aurora/absorption and NASA image engines do not download when constructed. They refresh only while a consuming map layer or solar-image pane is visible, provided public data feeds are allowed. Restoring a screen with visible layers can therefore initiate requests. Other services retain the triggers listed below; this control is not a global network switch. Opening this privacy page itself makes no network request. DNS lookups alone disclose a requested hostname to the configured resolver, even if a connection subsequently fails.

## Controls

- Public orbit/space-weather/image feeds: **Settings → Data Safety → Public data feeds**. Allowed by default, but demand-driven: no request or network refresh timer from engine construction alone. Disable to cancel pending requests and stop timers; cached/bundled data remain available. Visible consumers resume on re-enabling. Multiple windows share one timer per feed; hiding the last consumer stops it. This does not control MapKit, accounts, weather or other propagation tools.
- Weather: **Settings → Antenna Weather Radar**. New installations start disabled. Existing enabled/disabled preferences are preserved; the new precision preference defaults to a 4-character square for everyone. The precision choice applies to manual, timer, home and rover requests. Disabling cancels the pending weather task and discards its results; it cannot retract coordinates already received by a provider. Forecasts for a coarse square may differ substantially from local conditions and are not lightning detection or a safety guarantee.
- New-QSO uploads: **Settings → ADIF Live Sync → Zero-Click Cloud Outbox** has a master switch and QRZ, Club Log, eQSL, Wavelog and LoTW switches. These existing preferences default on but require configured accounts (and TQSL/location for LoTW). Network failures may remain queued and retry. Disabling prevents subsequent dispatches; it does not recall an upload already in flight. Scheduled sync and manual uploads remain separate in **Sync Center / QSL Hub**; Wavelog, HRDLog and HamQTH have their own automation controls.
- Upload field sharing: **Settings → Data Safety → Logbook upload privacy**. Name/QTH, contact details plus precise positions, and comments/QSL messages each require an opt-in (all default off). Callsigns, QSO/award fields and grids up to six characters still leave; this is not anonymous uploading. Unknown fields, `APP_*` and `*_INTL` are excluded. LoTW uses a separate signing-field set; TrustedQSL also supplies its configured station location. Queue previews do not override the policy at send time. Local exports/database records retain all fields.
- Rank enrichment/backfill displays a disclosure before the batch starts. Cancelling it makes no batch lookup requests. Bulk contact enrichment shows its destinations beside the start action. Credentials are managed through YAAM’s credential vault; external services receive the credentials needed for their own requests.
- Local servers, monitoring, cloud folder sync and webhooks each have their own enable/connect controls. A configured remote host is not necessarily local, even for a radio control feature.

## Local cards and lookup examples

Generated QSL PNG/PDF cards use the original bundled artwork for station callsign EP2AES (case/whitespace normalized), with a generic design for other stations or unavailable artwork, and the active station profile. QTH, country, valid CQ/ITU zones and flag are omitted when unknown. Previewing or exporting a card makes no network request; emailing it shares the resulting card and attachment with the recipient/mail provider.

Bundled demonstration membership/history/verified-call entries no longer populate operational lookups. Imported rosters, cached downloaded lists and history learned from the operator’s log remain available. Maps use a neutral origin when no location is configured; that origin is a display fallback, not a claim that the station is there.

### Credential vault boundary

YAAM's current vault uses AES-256-GCM and a random 256-bit root held in a non-synchronizing, device-local macOS login Keychain item (`ASIS.YAAM.ProtectedVault.v1` / `random-root-key`). Public hardware/account metadata cannot derive this root. The encrypted vault file alone is not a portable credential backup. Readable legacy files/defaults migrate once; removal follows verified encrypted persistence. Missing/denied keys or corrupt data fail closed and preserve the existing file. Background Keychain access does not request authentication UI or fall back to plaintext.

The optional Touch ID/Mac authentication preference gates the application's credential session. It is not a Secure Enclave claim or a per-item biometric ACL. Locking clears cached values; authorization results from before that lock cannot reopen it. Keep the matching Keychain item and encrypted file for same-Mac recovery; re-enter credentials on another Mac. Tests use synthetic values and isolated stores, not production credentials.
